# Campaign evidence pack

This directory is the immutable hand-off from capture and production to the
independent launch critic. Missing evidence is a blocker, never an inferred
pass.

```text
evidence-pack/
├── manifest.json         immutable candidate evidence audited by the critic
├── publication-manifest.json  post-GO envelope for critic result + README GIF
├── release/              commit, tag, public paths and quality-gate result
├── product/              binary hash, version and live tools/list
├── capture/
│   ├── raw/              OBS MKV sources: real PTY + real Chromium
│   ├── promoted/         stable verified indexes; one per scheduled master
│   ├── runs/             immutable per-run PTY, wire, browser and OBS evidence
│   └── product-probe/    optional browser-only support; never picture authority
├── edit/                 campaign brief, claim ledger, EDL, captions, posters
├── audio/                populated and signed by the audio production step
├── masters/              final MP4/VTT, ffprobe and SHA256SUMS
├── qa/                   automated report and human panel records
├── reproduction/         commands, tool versions, logs and clean-render comparison
└── signoffs/             marketing/audio before audit; critic result after it
```

The OBS capture adapter owns `capture/raw`, the immutable run directories and
`capture/promoted/<master-id>.json`. The promoted index is written atomically
only after `verification.passed=true`; it binds the raw MKV and every real PTY,
MCP wire, process, store, browser, OBS and run-manifest artifact by SHA-256.
Consumers resolve that index instead of guessing the newest UTC run. The
browser product probe may write supporting evidence under
`capture/product-probe`; it cannot substitute for an OBS raw picture.

Every scheduled picture must contain both real windows. `Process A` and
`Process B` are the only permitted identities until raw evidence proves a real
Codex or Claude host. The wrong-turn capture must display `DETERMINISTIC PRODUCT
FIXTURE`.

`manifest.json` is generated by `scripts/build-evidence-manifest.py`. It stays
`incomplete` until every pre-audit path exists and hashes cleanly. The launch
critic records that exact manifest hash in `signoffs/launch-critic.json`; the
critic result is deliberately not folded back into the manifest it audits.
After a `GO`, the sole README GIF is derived and
`scripts/build-publication-manifest.py` binds the candidate manifest, critic
result, derivative, source master and README. The muted-mobile panel is exactly
five distinct independent humans, each reviewing the exact three master
hashes. The audio panel is a separate independent human with documented
audio-training context. Empty files, agent reviews, OCR and inferred answers do
not count; the repository prepares a `PENDING` response template but never
manufactures either approval.

`scripts/freeze-product-evidence.py write` authenticates the downloaded release
candidate, its checksum and its live `tools/list`, then records the candidate
manifest, product commit and planned tag. Portable `check` validates that
frozen identity without requiring `target/` or a downloaded binary in the
checkout; `check --binary ...` additionally repeats the live MCP probe. Neither
mode manufactures a public quality-gate result or a human sign-off.
