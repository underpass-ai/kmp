# Audit reference: Inspect and Trace

VERB audit. Use kmp_inspect when one ref must support a claim; use kmp_trace when the connection between two refs is itself the claim. Do not guess or rebuild refs. Minimum input: exact about and exact returned refs. Expect: canonical object, evidence and links, or an ordered proof path. Next: follow pagination and cite stored evidence byte-for-byte. Inspect uses the owning about. Trace can cross a declared, evidenced same_event_as or same_entity_as edge; naming a foreign endpoint alone creates no path. Inspect keeps the stored object stable and pages expandable evidence and links; budget guidance distinguishes the stable floor from omitted expansion. Use include.raw for audit records, not for routine lesson reading. After retaining the first inspect object, continue with page.cursor and page.repeat_object=false to receive only object.ref plus the remaining expansion. object_reused=true declares that reuse. Keep the original text, kind, metadata and source; do not replace them with the ref-only object. Execute Inspect next_actions to continue with the complete bound call. If no whole item fits, page.minimum_progress_bytes names a sufficient next-item allowance. The action offers at least that much and prefers the complete inspection up to the usual 10,000-byte budget, avoiding a one-item-per-call walk. page.required_bytes still sizes the complete inspection. A fixed budget means the result remains partial. A changed object or selected proof returns conflict and a complete restart in feedback; that fresh read returns the new full object even if prior pages reused it. Omit repeat_object to receive the full object on every page. Trace also pages whole relations under budget.max_bytes. If page.returned is zero and page.has_more is true, this is pending proof, not an absent path: retry the same page.next_cursor with budget.max_bytes at least page.required_bytes. Trace next_actions contain the exact continuation. A changed endpoint or selected proof, including a later edge, rejects the cursor with a complete fresh-read action in feedback. The cursor is not a persisted snapshot; restart instead of mixing old pages with new evidence. For a write receipt, execute the returned receipt.action: object.text is immutable accepted-command JSON containing canonical_memory, writer diagnostics and command revision/hash. It is not the current state of the memories. Receipt refs stay within their owning about and do not enter graph traversal. Choose one Trace mode. Destination mode uses known to refs; evidence mode uses search.seek without to. The schema names each mode and its allowed fields. Work limits and optional proof are shared search controls. A mixed-mode rejection enumerates all incompatible fields together before their bodies are parsed; it does not enumerate every possible validation error. Destination mode: use to as an array of up to eight entry refs, or provide search, as_of or interval. All destinations share max_nodes/max_edges/max_depth/max_states. max_states counts the admitted root and eligible extensions attempted, including rejected cycles and visited nodes. direction selects outgoing prerequisites or incoming dependants without reversing stored arrows. relations filters exact link types. This mode stays in one about. Use as_of with a returned ref or time, or a half-open interval, and choose axis for occurred, observed, ingested or validity. An explicit clock never falls back to another. Canonical coordinates admit entries and relation clocks admit links. Default reads the current graph; neither bounded destination search nor evidence seek traverses equivalences into another about. By default it returns one shortest discovered route per explicit target. search.paths_per_target (1..8) retains bounded simple alternatives. search.follow is an unordered set of {rel, direction} moves instead of global direction/relations: for example incoming corrects then outgoing verified_by can reach a correction and its verification while preserving stored arrows. It does not require that order or infer complete answer evidence. Join every trace page, then resolve each routes[].edge_indexes into that complete table in hop order. An empty route is a zero-hop destination equal to from. search.stop_reason distinguishes targets_reached, frontier_exhausted, node_budget, edge_budget, depth_budget, state_budget and source_outside_selection. targets_reached means requested route quotas, not all paths: incomplete_targets have fewer than the quota; unreached_targets have none. from itself requires only its zero-hop path. Reconstruct walking direction from search.from and each stored edge; follow lists the allowed moves. Counts include discarded endpoints, dimensional labels and coordinate rows; coordinate_rows is part of scanned_edges. A ref cut resolves from the earliest coordinate on the chosen axis, within the same budget. If temporal_selection_resolved is false, stop_reason identifies the exhausted allowance: no instant was guessed. clock_unknown_edges identifies selected links with no usable clock; these do not prove historical presence. A cutoff never proves no path; rerun with a deliberate larger search allowance as a new selection if needed. Transport next_actions only finish the selected relation table; they do not continue the graph search. Frontier exhaustion and leaves are relative to the selected about, direction and rich relation types. Use temporal verbs to discover dated entries and inspect for entry/source bodies. Trace does not evaluate supersession or determine current truth from its path. See the bounded-trace example, including mixed directions and alternative paths. Optional search.select chooses a joint set before returning full links: max_material_nodes is required and counts unique entry refs on selected paths, including from; max_paths defaults to 4. Omitted groups means one equally weighted requirement per sorted target. Explicit groups contain alternatives: each ref array is an AND, arrays within a group are OR, weight defaults to 1; use only refs listed in to. Requirements come from the reader, not inferred truth. The fixed bounded beam can miss a better combination. search.material reports candidate_count, selected_candidates (original catalogue indexes), material_nodes, covered_groups, incomplete_groups, benefit and selection work. Group indexes follow the supplied groups or sorted targets. Discovery quotas remain separate. If no complete group fits, selected paths may be empty although candidate_count is positive. Finish next_actions for selected proof; only if more alternatives are needed execute search.material.expand_candidates. That complete call removes select and the old cursor and starts a new selection, not a historical snapshot. Its context cost is additional. Changes to unreturned candidate evidence also invalidate selected pagination. See bounded-trace for atomic, AND/OR and infeasible examples. Bounded search.dimensions reuses the native dimensional selection shape as a hard constraint on the source and every path entry. search.prefer_dimensions uses that shape only for soft ordering: three priority turns prefer matching nodes, then one FIFO turn. Each turn reads at most four raw relations or replays four cached admitted rows. An unfinished parent retains its exact position and requeues after newly discovered children. Priority ties prefer smaller effective depth and enqueue order; a resumed parent competes at child depth. It can reach a longer path first and has no shortest-path guarantee. Neither preferences nor FIFO promise completeness under work limits. Both stay in current_about and reuse only coordinates admitted on the selected clock, including for whole-entry selectors; a missing label here means absent from that admitted coordinate set, not proof of global absence. Ref cuts resolve before dimensional filters. Coordinate reads consume the shared N/E budget. Preserve nonmatching bridges with prefer_dimensions when a label is merely a hint; hard dimensions can exclude them. search.routing reports evaluated_entries, preferred_entries, dimensional_rejections, priority_pops, exploration_pops and preferred_route_entries aligned with returned routes, counting source. These are routing observations, not truth or relevance probabilities. Unfiltered calls keep BFS and its existing cost. search.routing.order identifies dimension_focus_pages_v2; adjacency_pages and coordinate_pages count actual storage calls including empty end probes, and resumed_states counts turns on a path already started. Alternative paths share partial admitted adjacency without rereading it, while extension attempts still spend S. A cut parent is not a leaf. Unread late edges or whole-label coordinate admission can still exhaust N/E before useful children progress. Histograms, rarity and degree scores are not supplied by this policy. See bounded-trace examples for hard constraints versus soft focus. Each embedded memory read keeps one SQLite snapshot across its graph, bodies and sources. Separate calls, including continuations, open fresh reads; changed selected content can require restarting the cursor. For evidence discovery from a known seed without destination refs, use kmp_trace search.seek. Each required role names a relation with optional ordered via/after moves; labels constrain the main witness; same_ref equates named main-relation anchors or witnesses. same_labels intersects exact membership values across all roles; missing remains unknown and labels never prove identity. Inspect seek.status, missing_roles, candidates and joint groups; complete every page before resolving indexes. declared_obligations_complete refers only to the supplied obligations, not natural-language answer completeness. Seek replaces destination search policies; work limits and proof remain shared. Expand guide:kmp-agent:example:evidence-seek for simple, identity, temporal and deep examples. When the intermediate sequence is unknown, set via:"context" on a seek role. KMP discovers minimum-hop prefixes through justified links in both directions at the same cut, retaining equal-length alternatives. rel/direction still declare what to find; after remains explicit. Read context_hops and context_discovery. These are contextual leads requiring review: declared_obligations_complete remains false, and a verification of a neighbor is not thereby a verification of the seed. Longer prefixes to the same origin are omitted, not certified irrelevant. No question meaning or missing obligations are inferred. For the same action across contextual roles, same_ref accepts {role,at:"anchor"} as well as witness role names. Anchor means main-relation traversal start after via/context; incoming authorizes starts at its stored target action. Only equate verification and permission anchors when the question requires the same action. A verified copy and an authorized publication are different actions: adding anchor equality changes that question. Review candidate bindings and original sources after incompatible_obligations; never drop a required equality merely to obtain a group. For known-by questions, explicitly set axis:observed and as_of. A null resolved_as_of does not establish the requested historical cut. as_of means effective at the cut, not timestamp equality; UNKNOWN does not diagnose its cause. A role may join through its anchor and witness separately. Candidate anchor and binding endpoints preserve those identities; context still requires source review. See example:evidence-seek. Optional search.proof:true in either Trace mode fetches selected entry bodies and typed sources under the same snapshot and shared N/E. Join objects/supports/gaps as well as path tables across all pages. Body hash/revision, source metadata/time, admitted coordinates and support declaration clocks remain separate. Missing bodies retain has_body:false; budget exhaustion does not establish absence. proof.complete_groups indexes declared target requirements or seek groups and means fetched declared sources only; preserve unknown obligations, clocks and review_required. Every selected body participates in the cursor fingerprint, including objects not yet paged. Changed evidence requires a fresh selection. body_bytes counts canonical UTF-8 bodies, not response bytes or store allocations.

For body descriptors, named expansion and reader cards, read `guide:kmp-agent:example:reader-cards`. Those delivery options require `search.proof:true`. A fresh compact read omits `proof_refs`, `expect_selection` and the old page cursor.
