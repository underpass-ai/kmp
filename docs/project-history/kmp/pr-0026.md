## What changes

`kmp-mcp export` and `kmp-mcp import` with **no path** now mean the project's committed memory:

```bash
kmp-mcp export && git add .kmp/memory.jsonl   # after a session that decided things
kmp-mcp import                                # in a fresh clone
```

`.kmp/memory.jsonl` sits at the project root — the same root the data-directory rule already walks up to find. The store (`.kernel/`) stays machine state and stays auto-gitignored; the bundle is a different thing, and belongs to the repository the way a migration or a fixture does.

## The reason it is worth having

Measured on a real store: **adding one decision is a 2-insertion, 1-deletion diff.** The appended event, and the header's `event_count` going from 8 to 9. Append-only in the log is append-only in git.

And the added line is readable as it stands:

```
root: incident:checkout-latency | rev: 9 | by: tirso
  change: UPSERT memory_entry     …:decision:alert-on-amplification
  change: UPSERT memory_relation  …:depends_on:…:constraint:retry-budget
  reason: The constraint stops a caller creating amplification; the alert
          catches one that slips past it.
```

The rationale of every rich relation is in the diff, verbatim. **A pull request that also settled three questions shows them in review.**

## The refusals, which are the design

- **Only a project-scoped store gets the default.** An explicit `KMP_MCP_DATA_DIR` or the per-user store belongs to no repository. Both commands refuse *and name the rule that won*: `this store is not project-scoped: it resolved to '/home/u/.local/share/kmp/default' by the 'user' rule`. Guessing a file for them would write memory somewhere nobody chose.
- **`/kmp:restore` is written to refuse rather than to help.** Import requires an empty store because it is restore, not merge — replaying a bundle over existing memory could duplicate history or interleave two timelines, and neither has an answer the kernel could pick. The command is told explicitly not to delete a store to make itself succeed, and to offer the three real choices instead.
- **Export creates `.kmp/` on the first save.** Failing on a missing directory would make the convention useless exactly once per repository — at the moment someone first tries it.

## Also stated rather than left to be discovered

The skill and `mcp-stdio.md` both say it: **a bundle carries payloads as written, so a secret in memory is a secret in the committed file.** The hygiene of the bundle is the hygiene of the store.

## Surface

`/kmp:save` and `/kmp:restore` for Claude Code, `/kmp-save` and `/kmp-restore` for Codex, a section in the skill, and the maintenance-CLI block in `docs/operations/mcp-stdio.md`.

## Tests

`stdio_binary` now asserts the real contract in three parts, replacing an assertion that only knew the old one (`export without path exits 2`):

- outside a project → exit 2, and the message names the default it could not use;
- inside a project but with an explicit data dir → still exit 2, because an explicit dir belongs to no repository even when it sits inside one;
- project-scoped, **run from a subdirectory** because that is where anyone actually is → writes `.kmp/memory.jsonl` at the root and says where.
