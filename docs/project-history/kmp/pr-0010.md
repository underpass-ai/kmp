## Author's change description

## The bug, reproduced on a clean machine

Installing the plugin the way the README advertises produces a plugin whose MCP server **cannot start**.

```
cargo install kmp-mcp                     # ok, 30s, kmp-mcp 0.1.2 (store format 1)
/plugin marketplace add underpass-ai/kmp  # ok
/plugin install kmp@underpass             # ok, enabled
```

Then the launcher:

```
KMP plugin: missing executable ~/.claude/plugins/cache/underpass/kmp/0.1.0/bin/kmp-mcp
KMP plugin: build the local plugin bundle before installing it
```

`bin/kmp-mcp` is gitignored, so a marketplace install never has it — and "build the local plugin bundle" is not advice a user installing from the marketplace can act on. The skill and the commands install fine; only the server is dead, which is the part that matters.

## The fix

Both launchers (`.sh` and `.cmd`) keep preferring `bin/<binary>` — a release package pins the binary that plugin version was tested against — and fall back to the one on `PATH` when `bin/` is absent. If neither exists, the error now names both places it looked and how to get one.

Verified: with `bin/` removed, the patched launcher answers `initialize` and lists all 10 tools using the `kmp-mcp` from `cargo install`.

## Also in here

`serverInfo.name` was `"kmp-kmp"` — a blanket rename artifact, visible in every client's `initialize` response. Now `underpass-kmp-mcp`, matching the sibling `underpass-made-mcp`. Test expectation updated.

The README now leads with the plugin, since it is the install that also brings the skill and `/kmp:doctor`, and it works from the marketplace.

The same defect exists in MADE and is fixed in its own PR.
