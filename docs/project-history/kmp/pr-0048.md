## Author's change description

Fixes #40, fixes #42.

## A parameter that is not a number is refused by name

```
before: GET /api/graph?about=X&depth=abc   -> 200  (silently the default)
        GET /api/graph?about=X&scope=oops  -> 400  {"error":"unknown scope `oops`; ..."}

after:  GET /api/graph?about=X&depth=abc   -> 400  {"error":"parameter `depth` is not a number: `abc`"}
```

Two parameters guessed while the two beside them refused. This codebase argues the opposite everywhere else — `an_unknown_kind_is_refused_rather_than_guessed`, and the storage engine's "an unknown header is an error, never a guess" — and a typo that answers as if it were correct is the one failure a caller cannot see.

Two things deliberately unchanged: **out of range still clamps**, because a bound is a policy rather than a mistake, and **absent still means "use the default"**.

## HEAD is answered

RFC 9110 §9.3.2: HEAD is GET without the body. The viewer replied 405, so a health check or a link checker pointed at it reported it down.

The head is now byte-identical to what GET would send — `Content-Length` included, which is the part that makes the two answers agree — and the body is withheld at the socket rather than by emptying the response. Every other method is still 405; read-only stays read-only.

## The budget says what it budgets

At `budget=256` the status bar read `COMPRESSION ×142.9` beside a graph showing every one of 59 nodes, uncompressed. The number was true — about a rendering the reader never sees.

| before | after |
|---|---|
| `budget` | `context budget` |
| `TOKENS` | `CONTEXT TOKENS` |
| `COMPRESSION` | `CONTEXT COMPRESSION` |

with titles saying the graph is drawn whole either way.

**Why not budget the graph instead.** That was the other option in the issue, and it is the wrong one. A reader needs the whole neighbourhood to navigate — a viewer that hides nodes to fit a token budget is answering a question nobody asked at a screen. The budget exists to describe what an *agent* would receive at that size, and the viewer already shows exactly that, behind the Context button. Naming the control after the thing it bounds makes the pair honest; cutting the graph would make it useless.
