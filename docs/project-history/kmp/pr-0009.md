## Author's change description

## What changed

The README opened with a contributor quickstart (`cargo test`, `docker pull`), so the path most people actually want — the kernel running in-process inside Claude Code or Codex — sat 150 lines down under "Distributions". This reorders the documentation around what a reader is trying to do, and makes the embedded/cluster split explicit and consistent with MADE.

- **New `docs/editions.md`** — the canonical embedded-vs-cluster comparison: what each edition guarantees, what it does not, and how to move between them.
- **README** — opens with "Start here — pick an edition", with the real install for each host; contributor commands moved to "Developing this repo".
- **`docs/index.md`** — operations table regrouped by edition.
- **Vocabulary aligned with MADE** — "Embedded edition" / "Cluster edition" everywhere it said "Infrastructure edition" or "Local / embedded", and reconciled with the adapter's own "live mode" wording.
- **Integration guide renamed** to `made-kmp.md` after the MADE rename, edition table aligned, catalog repointed, superseded file deleted.

## Two documentation-vs-reality fixes

Both found while verifying the commands before writing them down:

1. **The plugin README claimed a marketplace install "brings the MCP server with it".** It does not: the launcher execs `plugins/kmp/bin/kmp-mcp`, and that path is gitignored, so it only exists in a release package or a locally built bundle. A marketplace install currently produces a plugin whose MCP server exits 127. The README now says so and points at `/kmp:setup`.
2. **The Operator note linked `docs/research/entrenando-un-modelo-pequeno-para-operar-kmp.md`**, which has never existed in this repo. Repointed at `docs/operator.md`.

## Follow-up worth considering (not in this PR)

`plugins/kmp/scripts/run-embedded-mcp.sh` has no fallback when `bin/kmp-mcp` is absent. Adding `command -v kmp-mcp` as a fallback would make the marketplace install path actually work, with the release bundle keeping priority.
