## The failure this comes from

I read the entire `kmp-memory` skill in one session, wrote an entry in a second about, and then **filed an issue asking for cross-project reading as a missing feature** — because I had understood scoping as a constraint on queries rather than as the mechanism for spanning abouts. It took a correction from the repository owner, and the capability turned out to work exactly as designed:

```
kernel_ask about: project:made
           dimensions: { scope: "abouts", abouts: ["project:made", "project:kmp"] }

evidence by about: { project:kmp: 46, project:made: 4 }
```

If someone who just read the whole skill reaches for the wrong thing, someone skimming has no chance.

## What was missing

Not more words about the parameter — the **use case and the design reason**:

> Abouts are not joined by relations, and that is the design rather than a gap. An edge between two projects would bake the link into the graph: anyone traversing MADE would drag KMP along whether they wanted it or not, and the frontier an about exists to bound would stop being bounded. So the join lives with the reader, at read time.

That paragraph did not exist anywhere, and it is the whole model. Without it, `scope` looks like a restriction to be obeyed instead of a capability to reach for.

## Three surfaces

- **The MCP schema** — the one the skill names as the authority ("read the schema in front of you rather than guessing"). `scope` carried no description at all; `abouts` said only `"Memory about id."` Both now say what they are for.
- **The memory skill** — the section was headed *"Scope is explicit"* and listed defaults and costs. It is now *"Reading across projects"*, leads with the worked example, and keeps the auditability rules where they belong: after the reason they exist.
- **The host guide** — had no user-facing account of reading one project's memory inside another project's conversation. It has one now, with the same example.

The costs stay stated. `all_abouts` is still a real cost on a large store; the difference is that scoping to the two or three abouts that bear on a question is now presented as the cheap, intended path rather than as a concession.
