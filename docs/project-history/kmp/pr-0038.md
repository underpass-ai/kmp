## Author's change description

Two fixes to the thing 0.1.4 shipped — two agent hosts on one memory — both found by chasing that promise to where an operator meets it rather than to where a test passes.

## What is in it

**#34 — the WAL switch.** ADR-018's spike concluded *"the fix is ordering, not retry logic"*, and the implementation inherited it. Measured:

| the other connection | switching to WAL |
| --- | --- |
| holds a **write** lock, database still in its default journal mode | fails **immediately** — the busy handler is not consulted |
| holds a **read** lock, database still in its default journal mode | waits the whole timeout, then fails |
| holds any lock, database **already** in WAL | succeeds; the switch is a no-op |
| merely connected, no lock | succeeds |

The window is only between a store file being created and its switch to WAL — two hosts starting against a data directory with no store yet, which is exactly the state after migrating — and inside it an armed timeout buys nothing. The spike README carries the measurements in place; leaving a measured-wrong conclusion in an evidence document is how it reached the code.

**#35 — the launcher.** It preferred the bundled binary, built without the sqlite engine, so `cargo install kmp-mcp --features sqlite` was installed and never used: the recipe ended at step 1. `KMP_MCP_BIN` names the executable and nothing else.

Both are gated where they broke. The sqlite gate now reproduces a release-bundle install and asserts both directions:

```
sqlite-gates: two hosts share one store through the plugin launcher
  bundled binary alone: refused, as it must
  host a with KMP_MCP_BIN: 10 tools
  host b with KMP_MCP_BIN: 10 tools
```
