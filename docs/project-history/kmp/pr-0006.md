## Author's change description

`v0.1.0` published five crates and then failed:

```
cargo publish -p kmp-adapter-embedded (0.1.0)
error: failed to prepare local package for uploading
Caused by: no matching package named `kmp-application` found
```

`kmp-adapter-embedded` dev-depends on `kmp-application`. A dev-dependency is
stripped from the published manifest **only when it carries no version** —
these inherit the workspace pins that the normal dependencies need, so the
edge is `^0.1.0` and cargo resolves it like any other. `kmp-application` now
publishes before it.

`check-publish-chain.sh` skipped dev-dependencies outright, so it encoded the
same wrong assumption as the order it was checking and passed. It now
simulates the publish — walking the chain while carrying the set of crates
already on the registry, and requiring every versioned internal dependency to
be in that set regardless of kind. Against the order that failed in CI it
reports:

```
::error::kmp-adapter-embedded is published before its dev dependency kmp-application
```

Bumps to **0.1.1**. The five crates published at 0.1.0 stay at 0.1.0 —
registry versions are immutable and we do not move tags — so 0.1.1 is the
first version where the whole chain, `kmp-mcp` included, is installable.
The CHANGELOG says so plainly rather than letting 0.1.0 claim a chain it
did not deliver.
