## Author's change description

## Qué hace

Convierte el plugin de KMP en un artefacto publicable y autocontenido (mismo patrón que underpass-ai/made#1):

- **Bundle autocontenido**: `.mcp.json` ya no asume `kmp-mcp` en PATH — el plugin lleva el binario en `bin/` y lo arranca con `scripts/run-embedded-mcp.sh` (o `run-embedded-mcp.cmd` en Windows). El launcher selecciona el backend embebido y NO elige data dir: el kernel resuelve `KMP_MCP_DATA_DIR` → project root → data home del usuario, como manda la doctrina.
- **Manifiesto Codex**: nuevo `.codex-plugin/plugin.json` junto al existente de Claude Code; ambos se estampan desde la única fuente de verdad (workspace `Cargo.toml`).
- **`scripts/plugin/package-kmp-plugin.sh`**: genera `dist/plugin/kmp-plugin-<version>-<os>-<arch>.tar.gz` + `.sha256`. En tag `v*` exige tag == versión workspace o falla; builds de dev llevan `+<short-sha>`.
- **CI (`plugin-package.yml`)**: matriz linux-x86_64, linux-arm64, macos-arm64, windows-x86_64 (con protoc por plataforma, replicando release.yml); smoke contra el binario real + empaquetado en cada una; artifacts en cada run y adjuntos al GitHub Release en tags.
- **Smoke nuevo** (`scripts/ci/kmp-plugin-smoke.sh` + `tests/plugin/kmp-smoke.jsonl`): valida manifiestos (rechaza versiones divergentes), compila el bundle y ejecuta initialize + tools/list contra un data dir aislado, exigiendo `kernel_wake`, `kernel_ask`, `kernel_write_memory` y `kernel_trace`.
- Docs: README del plugin con instalación desde el paquete de release y nota Windows.
