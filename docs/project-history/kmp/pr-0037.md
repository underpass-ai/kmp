## Author's change description

Fixes #35. Found while replicating ADR-018 in MADE, where the same gap existed (made#19).

## The recipe ended at step 1

`docs/operations/mcp-stdio.md` tells an operator who wants two agent hosts on one memory to:

1. `cargo install kmp-mcp --features sqlite`
2. `kmp-mcp migrate <old> <new> --engine sqlite`
3. point both hosts' `KMP_MCP_DATA_DIR` at the shared directory

If those hosts run KMP through the plugin, step 1 is installed and never used. The launcher prefers the bundled `bin/kmp-mcp` over anything on `PATH` — correctly, since a release bundle pins the binary that plugin version was tested against — and that bundle is built without the engine. The bundled binary then refuses the migrated store:

> the kernel store is a SQLite database and this binary was built without that engine

Correct, and useless: there was no way to say "run the one I built".

`kmp-doctor.sh:34` already read `KMP_MCP_BIN`. A doctor that diagnoses one binary while the launcher runs another is diagnosing the wrong thing.

## The fix

`KMP_MCP_BIN` selects the executable and **nothing else** — the backend and the kernel's own data-directory resolution (`KMP_MCP_DATA_DIR` → project root → per-user data home) are untouched, because overriding a binary is not a request to configure the rest by hand.

## Gated where the operator meets it

The sqlite gate now copies the plugin, gives the copy a bundled binary built **without** the engine — reproducing a release-bundle install — and drives the real launcher twice at once against one shared store:

```
sqlite-gates: two hosts share one store through the plugin launcher
  bundled binary alone: refused, as it must
  host a with KMP_MCP_BIN: 10 tools
  host b with KMP_MCP_BIN: 10 tools
```

Both directions are asserted. Without the negative half the gate would pass in a checkout that has no `bin/` at all, proving nothing — which is how this gap survived in the first place.

## Also

The Windows launcher ran `"%BINARY%" %*`. A leading argument is read as a maintenance command (`migrate`, `--version`), so a host that passed anything would get exit 2 and no tools — on Windows only. The POSIX launcher already dropped them; they now agree.

## Docs

`mcp-stdio.md` (the recipe and why the variable exists), `embedded-hosts.md`, `plugins/kmp/README.md`, and `kmp-doctor`'s advice when it finds a redb store held by another process — that advice previously named the migrate command and stopped there.
