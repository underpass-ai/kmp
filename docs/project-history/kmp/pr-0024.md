## What I found

I set out to build "delta since last session" and went looking for where to add it. It is already there:

```
kernel_rewind  from: { time: <now> }, limit: { entries: 1 }, budget: { detail: "full" }
  -> newest entry, with coordinates[].observed_at   ← the bookmark
  -> page.total                                     ← how much the memory holds

kernel_forward from: { time: <that> },              budget: { detail: "full" }
  -> exactly the entries after it, in order
  -> page.has_more                                  ← was the slice cut
```

Verified on this project's own memory: the frontier came back at `18:30` of 13 entries, and forward from `17:00` returned exactly the 4 after it with `has_more: false`.

So the gap was never capability. It was that the pattern takes two moves with parameters nobody would guess — `detail: "full"` is what makes the coordinates carry their timestamps, and without it `occurred_at` comes back empty and the bookmark is unobtainable.

## What this adds

**No move.** The ten moves are a design constraint, not just a tagline; an eleventh for something two of them already do would make the surface worse and the docs longer.

- `/kmp:catchup [about] [since]` for Claude Code, `/kmp-catchup` for Codex.
- A **Catching up** section in the skill, placed with the temporal moves, so an agent finds it at the moment it would otherwise start re-reading files.

Both commands are written to fail honestly: an empty memory is reported as empty rather than as an error, a truncated slice is never presented as the whole delta, and *"nothing changed since Friday"* is a complete answer rather than something to pad.

The skill also records the design reason the kernel does not remember where each reader got to: **a memory that tracked its readers would be keeping state about you rather than about the work.** The bookmark is the caller's to carry.

## Follow-up filed separately

`kernel_wake` returns `proof`, `summary`, `wake`, `warnings` — no cursor. So the natural flow (wake to get oriented, then catch up) needs a second call to `rewind` purely to learn a timestamp that wake already had in hand. That is an ergonomic gap worth closing, but closing it means a field on `WakeResponse`, which is a contract change across the proto, the vendored copy, the fixtures, both backends and conformance. It should not ride along inside a docs PR. Filed as an issue with the design.
