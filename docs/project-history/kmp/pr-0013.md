## Author's change description

## The bug

`kernel_write_memory` wrote nothing unless the caller explicitly passed `options.dry_run: false`.

```rust
let dry_run = options
    .and_then(|options| options.get("dry_run"))
    .and_then(Value::as_bool)
    .unwrap_or(true);          // crates/kmp-mcp/src/write.rs
```

The call still returned `isError: false`, so an agent reported success to the user. Only `accepted: false` in the structured payload gave it away. The next `kernel_wake` failed with `node 'project:demo' not found`.

Reproduced against the published 0.1.3, with a perfectly valid rich relation and full evidence:

```
WRITE -> isError: False | accepted: False | dry_run: True
WAKE  -> embedded kernel wake failed for `project:demo`: node 'project:demo' not found
```

## Why nothing warned

Everything that documents the tool describes committing as the normal path:

- The JSON schema said *"When true, only return the compiled canonical kernel_ingest preview"* and stated **no default**.
- The skill (`plugins/kmp/skills/kmp-memory/SKILL.md`) says the tool *"supports `options.dry_run` to check before committing"* — previewing as the opt-in.
- `docs/product/kernel-write-protocol-plan.md` says *"When `dry_run=false`, the tool validates, compiles, and forwards to..."*.

An agent reading the contract had no way to learn it must pass the flag.

## The fix

The default flips: a tool named `write_memory` commits, and previewing is opt-in. The schema now states the default so it is visible in the contract.

## Verified end to end

With the fix, a call carrying **no `options` at all**:

```
WRITE sin options -> isError: False | accepted: True | dry_run: False
WAKE              -> isError: False | contains the decision: True
```

New test `write_commits_unless_a_preview_is_requested` covers both the no-options shape and the case where an unrelated option (`strict`) is set — that must not turn a write into a preview either. The existing `dry_run_generates_canonical_ingest_preview` now asks for the preview explicitly.

## Related

A separate trap found in the same session, filed as an issue rather than fixed here because it needs a design decision: on a brand-new `about`, `kernel_write_memory` cannot succeed at all. Strict mode requires at least one `connect_to`, `connect_to.ref` must reference an existing ref, and a fresh `about` has none — not even its own anchor node (`references unknown refs`). Seeding currently requires dropping to `kernel_ingest`.
