## Summary

- replace the repeated `dtolnay/rust-toolchain` setup with one repository-owned composite action
- read the pinned channel from `rust-toolchain.toml`
- retry `rustup toolchain install` up to three times with bounded backoff
- preserve per-job components and release targets on Linux, macOS, and Windows
- make shared installer changes exercise the cross-platform plugin packaging matrix

## Why This Belongs In The Kernel

This is repository-level CI reliability for KMP itself. It does not add integrating-product concepts or change a runtime boundary.

## Root Cause

The unresolved `integration-conformance` failure cited by #30 never reached a test or container. Historical job `95192653017` failed after 405 ms in `rustup toolchain install 1.97.1` with `Connection reset by peer`; every other job on the same commit passed toolchain setup. PR #55 already fixed the separate projection-convergence race in `kernel_full_journey`.

The shared installer makes that transient download failure self-healing while keeping real configuration failures bounded to three attempts.

## User / Developer Impact

A one-off reset from `static.rust-lang.org` no longer turns an otherwise valid PR or release into a false red that needs a manual rerun.
