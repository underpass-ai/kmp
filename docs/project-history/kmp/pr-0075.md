## Author's change description

## Summary

Run the existing `relation_materialization_integration` target in the required `integration-conformance` job, immediately after the infrastructure-adapter conformance suite. Document that this end-to-end path is now part of required CI.

## Why This Belongs In The Kernel

`graph.relation.materialized` is a kernel-owned async boundary. Its NATS → projection runtime → Neo4j/Valkey → gRPC guarantee should be enforced by the kernel repository rather than left as a manual-only test.

## Root Cause

The end-to-end test existed and passed locally, but no required workflow invoked its Cargo test target. A regression could therefore merge while the documented coverage remained green only when a developer remembered to run it.

## User / Developer Impact

Every candidate tree now proves that a relation-only event extends the graph through the real infrastructure adapters without rematerializing its source node.
