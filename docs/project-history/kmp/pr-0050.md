## Author's change description

Fixes #14.

## The deadlock

Three rules, each reasonable, jointly unsatisfiable on a new about:

1. strict `kernel_write_memory` requires at least one `connect_to`
2. a relation target must be an **existing** ref
3. a fresh about contains nothing to reference

Relating to the about itself — the obvious thing a caller writes — failed as well:

```
embedded kernel ingest failed for `project:nuevo`: memory relation
`project:nuevo:entry:decision:primera-decision` -> `project:nuevo` references unknown refs
```

## The refusal was wrong on its own terms

The about's anchor **is a real node**. The projection materialises it, hangs `records` and `has_dimension` off it, and the viewer draws it as `memory_anchor`. It simply was never added to the ingest's set of known refs — so the one node that certainly exists could not be named as a relation target, on any about, new or old.

Adding it to that set is the entire change:

```rust
known_refs.insert(about.to_string());
```

## Why this rather than the alternatives

The issue offered three directions and called it a doctrine question rather than a mechanical fix. It is worth saying why this one:

- **Allowing an empty `connect_to` when the about is empty** weakens what strict guarantees, and costs the writer a read before every write to know whether the about is empty. It also treats the first entry as unconnected, which is not true — the anchor records it.
- **Inventing a placeholder node** adds something that carries no observation.
- **A separate seeding intent** adds a second way to write in order to preserve a constraint that was never actually violated.

`strict` is untouched here. It still demands a relation that carries its why, and the first entry of an about genuinely does stand in a relation to the about it belongs to. Nothing is weakened, nothing is invented — a set that was missing a member now has it.
