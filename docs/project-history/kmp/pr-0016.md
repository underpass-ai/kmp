## Author's change description

## Why

Three defects shipped this week, all in the same gap — between *the bundle builds* and *the host starts it* — and all leaving an install that looks correct and does nothing:

| Defect | Symptom for the user |
|---|---|
| Launcher exec'd `bin/kmp-mcp`, gitignored and present only in a release package | exit 127, telling them to build a bundle they cannot build |
| Plugin manifests stamped 0.1.0 through every release | `claude plugin update` says "already at the latest version" forever |
| `.mcp.json` declared `cwd: "."` with a relative command | `ENOENT: posix_spawn './scripts/run-embedded-mcp.sh'` |

`kmp-plugin-smoke.sh` missed all three, and not by accident:

- it runs `build-local-kmp-plugin.sh` **before** testing, so `bin/` always exists and the marketplace shape is never exercised;
- it invokes `scripts/run-embedded-mcp.sh` **by path**, so the `.mcp.json` the host actually reads is only parsed for valid JSON;
- it compares the two manifests **to each other**, so both being wrong passes.

It is a good gate for what we package. Nothing gated what a user receives.

## What this adds

`scripts/ci/kmp-plugin-install-smoke.sh` — the host's side of the same plugin:

1. **Marketplace shape.** Copies the *tracked* plugin files via `git ls-files`, so a local build tree cannot smuggle in a binary the host would never get, and asserts `bin/` is absent.
2. **Version the host will report.** Compares both manifests against the workspace version in `Cargo.toml`, not against each other.
3. **PATH fallback.** Builds `kmp-mcp` and puts it on `PATH` — what `cargo install kmp-mcp` leaves a user with, and the only binary a marketplace install can find.
4. **Started the way the host starts it.** Reads the command out of `.mcp.json`, expands `${CLAUDE_PLUGIN_ROOT}`, rejects a declared `cwd` or a relative command, and spawns it **from a directory that is neither the repository nor the plugin**.
5. **The surface.** Asserts `initialize` answers and all ten `kernel_*` tools are advertised.

## Verified against each historical failure

Reverting `.mcp.json` to the form we shipped:

```
server kernel-memory declares cwd='.'; the host does not resolve it to the
plugin directory, so the command must stand on its own
```

Pinning a manifest back to 0.1.0:

```
KMP plugin install smoke: .claude-plugin/plugin.json says 0.1.0, workspace says 0.1.3
```

With both correct:

```
started 10 tools from a marketplace-shaped install
KMP plugin install smoke passed
```

## CI

Wired into `plugin-package.yml` before the packaging step, so a broken install fails the job whether or not the bundle builds. Linux only: the declaration points at the shell launcher, and the Windows host reads the `.cmd` twin that the bundle smoke already covers.
