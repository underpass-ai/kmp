## Author's change description

Step 1 of 3 for [ADR-018](https://github.com/underpass-ai/kmp/pull/17). **No behaviour change.** This PR introduces the seam and moves redb behind it; the conformance suite passing unchanged is the proof the seam is faithful. SQLite comes in step 2, engine selection in step 3.

## What moves

Every port — event log, graph reads, projection writes, node details, runtime state, snapshots, migration receipts — was written directly against redb's typed tables and transactions. It is now written **once** against a narrow seam (`adapter/engine/mod.rs`):

- eleven tables, each with a fixed key shape (`Str`, `Str2`, `Str3`, `U64`) and bytes for a value;
- exactly the operations the ports already performed: `get`, `insert`, `remove`, ordered scan, scan by first key component, `last` of a `u64` table, `count`, `clear`;
- read and write transactions as trait objects.

No port file names an engine type any more. `grep redb crates/kmp-adapter-embedded/src/adapter/*.rs` finds only the migration's file-copy comments.

Behind it, `adapter/engine/redb.rs` owns the table definitions and the file — the same names, key types, value types and layout as before, so **existing stores open unchanged**.

## Two contracts made explicit

The ports relied on both without saying so; the seam documents them because a second engine has to honour them too:

- **Rows come back in ascending key order, byte-wise per component.** The neighborhood output depends on it.
- **A table that has never been written reads as empty.** That is how a store nobody migrated reports "no receipt".

## Design choices worth a look

**Dynamic dispatch, not generics.** `EmbeddedKernelStore` stays one concrete type holding an `Arc<dyn Engine>`. The alternative — `EmbeddedKernelStore<E>` — would push a type parameter up through `kmp-embedded` and `kmp-mcp`, and step 3 wants one binary that picks the engine at open time from config or the data-dir marker. One vtable hop per transaction is the price; it does not show up anywhere measured.

**Tables opened per operation.** A redb write transaction refuses a second live handle on the same table, and holding handles across seam calls would need the transaction and its borrowers in one self-referential struct. Opening an existing table is a root lookup inside the transaction. The 100k scale run below is the check that this is free in practice.

**Scans return `Vec`, not iterators.** Every caller collected before this seam existed, so nothing is lost, and it keeps the traits object-safe without a lifetime tying a row to its transaction.

**Telemetry untouched.** The quality journal (ADR-014) is a separate redb file with its own relaxed durability. It borrows the redb error mappers from the engine module, which is where they now live; otherwise it is not part of this change.
