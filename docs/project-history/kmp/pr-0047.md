## Author's change description

Fixes #41.

## The time column was the sort key

Times are stored as `unix:<seconds + offset>:<nanos>`, zero-padded so that byte order equals time order. That is exactly right for a store, and it was being printed in the one column of a timeline that has to be legible:

| before | after |
|---|---|
| `work unix:101786903200:000000000` | `work 2026-08-16T18:00:00Z` |

Rendering happens in the viewer's API, so the raw form stays internal and every surface downstream gets a readable one. Anything that is not that form — times ingested as RFC3339 — passes through untouched.

The conversion is Hinnant's civil-from-days rather than a new dependency: this crate's README makes a point of shipping nothing the embedded edition does not already carry, and a date library for one format string is not the place to break that. Tests cover the epoch, a second before it, a leap day, and 2100 — the century rule that catches naive implementations.

## `SNAPSHOT pending` was forever

```rust
// crates/kmp-domain/src/value_objects/bundle_metadata.rs
pub fn initial(...) -> Self {
    Self { revision: 1, content_hash: "pending".to_string(), ... }
}
```

Nothing in the embedded path replaces it. So the status bar showed a word that reads like a state on its way somewhere — next to `REV 1`, which also never moves — and it would have read that way forever.

I did not make up a hash. A field that can only say one thing is not information: `content_hash` is now `Option<String>`, omitted from the payload when it is the placeholder, the status bar hides the stat, and the Context pane says `no snapshot hash for this recall` instead of `sha256 pending`. If the kernel ever computes one, it appears with no further change.

**One CSS line came with it**, and it is the kind of thing that would have made this fix look like it did nothing: `.stat` sets `display: inline-flex`, which beats the `[hidden]` attribute. Hiding the stat from script alone left it on screen.

## Verified against a real store

- timeline rows: `2026-08-16T18:00:00Z` where they read `unix:101786903200:000000000`
- status bar: `REV 1 · NODES 68 · EDGES 167 · TOKENS 3251 · COMPRESSION ×7.5 · CAUSAL 37% · NOISE 0%` — no snapshot field
