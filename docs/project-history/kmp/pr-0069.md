## Author's change description

## Summary

- make CLI help, strict first writes, doctor diagnostics, and data-directory setup reliable
- add question relevance and a hard final budget for compact MCP responses
- ship SQLite-capable embedded defaults while preserving stamped redb stores
- keep MCP available through transient redb single-writer locks and retry backend startup

## Root causes

Operational paths had diverged from the first-start and existing-store safety invariants. Graph proximity was also being treated as question relevance, response budgeting stopped before final serialization, and eager redb initialization made an ordinary lock conflict abort MCP startup.

## Impact

Fresh default embedded stores use SQLite for multi-process operation. Existing stamped redb stores remain redb and are never converted implicitly. Strict graph validation remains enforced after the initial about root exists.
