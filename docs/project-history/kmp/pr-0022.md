## Author's change description

## The bug

```
$ cargo install --git https://github.com/underpass-ai/kmp --branch main kmp-mcp --features sqlite
error: package `kmp-mcp v0.1.3` does not have a dependency named `kmp-adapter-embedded`
```

`crates/kmp-mcp/Cargo.toml` had `sqlite = ["kmp-embedded/sqlite", "kmp-adapter-embedded/sqlite"]`, and `kmp-adapter-embedded` is a **dev-dependency** of `kmp-mcp`. Inside the workspace `cargo build`/`cargo test --features sqlite` resolve it and go green — which is why #19's gates passed. `cargo install` resolves without the workspace and without dev-dependencies, and refuses. It is the one command a user runs to get this binary, and nothing ran it.

Found by installing from `main` on my own machine, right after telling someone that was the way to get the engine.

## The fix

`sqlite = ["kmp-embedded/sqlite"]`. `kmp-embedded` already forwards to the adapter through a normal dependency, so nothing is lost.

## The gate

`scripts/ci/embedded-sqlite-gates.sh` now ends with `cargo install --path crates/kmp-mcp --features sqlite` into a scratch root and runs `--version` on the result. Same family as the marketplace-install smoke from #16: the failure lived between "it builds" and "a user gets it", and only doing what the user does catches it.

Verified: `cargo install --path crates/kmp-mcp --locked --features sqlite --root <tmp>` succeeds; default build unchanged.
