## Author's change description

Fixes #39.

## The root cause is the data, not the direction

I filed this issue saying `goto` could never be satisfied from the viewer. That was wrong, and so was my first correction. What is actually true:

`goto` and `rewind` walk by **temporal position**. Given a `ref` they take the position from that entry and work on any memory. Given only a **timestamp** they need the entries themselves to carry a position — and `sequence` is optional at ingest.

| memory | `goto` + ref | `goto` + time |
|---|---|---|
| the viewer's test corpus (every coordinate has `sequence`) | answers | **answers** |
| a real store written without `sequence` | answers | **0 / 0** |

That table is why nothing caught this: the one corpus the viewer is tested against writes a sequence on every coordinate, so the failing shape never occurs in a test.

## What the user saw

- **Replay**: `this about has no temporal entries to replay` — on an about with twelve. It asked for `direction=goto, seq=4294967295`, a sequence with no dimension or scope to count within.
- **Timeline**: a blank panel on its own default, with a thin grey `cursor: / <time> · 0/0 entries` line above it and no explanation.

## What changed

**Replay** asks `near` around now, wide both ways. It needs nothing selected and returns the whole line whatever the entries look like. Verified against a real store: replays 12 of 12 where it used to claim there were none.

**The Timeline defaults to "around a time"**, and the labels now say what each direction walks from:

| before | after |
|---|---|
| `known at` (default) | `around a time` (default) |
| `near` | `forward from a time` |
| `rewind` | `at a selected entry` |
| `forward` | `back from a selected entry` |

`known at` is precisely what invited a reader to pick a position-walking direction and hand it a timestamp.

**An empty answer says why**, and separates the two cases that used to look identical:

> No entry sits in that window. Try widening it, or another direction.

> "at a selected entry" walks from a temporal position, and nothing here carries one — these entries were written without a sequence. Select an entry in the graph to walk from it, or use "around a time".

The first is fixed by a wider window. The second never will be, and saying "no entries" to both is what made the panel look broken.

## Verification

Driven through the real viewer against a real store, not just the fixture:

- Timeline on its default: **8/12 entries rendered** where it was blank.
- Replay: **12 entries, playing**, where it claimed there were none.
- A position direction with nothing selected: the explanation above, instead of a bare panel.

The test pins the shapes the UI issues rather than the UI itself, since the panel is untested JS — including an explicit assertion that `goto`-by-time works in the corpus **because** every coordinate carries a sequence. The day that stops being true, the test says so instead of silently passing.
