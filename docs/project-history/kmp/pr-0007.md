## Author's change description

KMP loads a redb store written by another version — verified by writing with
a v0.1.0 binary and reading it back with v0.1.1, evidence included. What it
could not do is **migrate** one.

The fail-fast rule (ADR-012) rejects a `FORMAT_VERSION` the binary does not
support, and told operators to "run the migration tool". No such tool
existed: the only migration binary in the repo is `kmp-neo4j-migrate`, for
the Neo4j schema of the deployed edition. Export/import was not a way out
either — `import` refuses a bundle whose `store_format` differs, closing the
door exactly at the boundary where it would matter.

## `kmp-mcp migrate <source-dir> <destination-dir>`

```
{"source_format":0,"source_sha256":"1a5a…","destination_format":1,
 "events_migrated":1,"mutations_applied":11,"kernel_version":"0.1.1"}
```

Built on the event log, not on the store file: projections are derived state
and their shape is what a format bump would change, so the migration replays
history into a fresh store and rebuilds them from it.

Guarantees, each asserted by a test:

- **The source is never opened for writing.** Hashed, copied, and the *copy*
  is what gets opened — so even redb's recovery after an unclean shutdown
  cannot touch the operator's evidence. The hash is checked again at the end;
  a mismatch fails the migration instead of reporting success.
- **The destination cannot already hold a store.** Re-running a finished
  migration reports that, with event count and source hash, rather than a
  bare conflict.
- **A receipt is persisted in the destination** and readable afterwards.

## Verified

- 9 new integration tests, including migrating a store stamped with an older
  format — the case that previously had no answer — and asserting the source
  is byte-for-byte identical afterwards.
- End to end with the real binary against a `FORMAT_VERSION=0` store: it
  migrates, the memory reads in the destination, the source keeps its hash
  and its stamp.
- `fmt`, `clippy -D warnings`, full workspace test suite, both contract
  gates.

Also fixed: the refusal message no longer names a tool that does not exist,
and a test pins that.

Scope note: one store format exists today, so a migration is a faithful
replay. The translation step for a future format belongs in the same module,
and `docs/operations/embedded-release.md` says so — the scaffolding ships
tested rather than promised.
