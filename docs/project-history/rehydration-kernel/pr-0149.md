## Author's change description

## What

`MemoryRelationSpec` joins `MemoryRecordRequest`: **from, to, rel, semantic_class, why, confidence, sequence** — the subset the first relation-writing consumer (the embedding product's precedent candidate index publisher) needs, not the kernel's full relation vocabulary. ADR-016 said relations would arrive with their first consumer; the consumer arrived. The embedded impl maps the spec onto the ingest relation (deeper fields stay `None`); `RecordedMemoryView` now reports `accepted_relations`.

## Semantics, stated where the consumer reads them

- A relation may join **entries of its record or refs the memory already holds** — not evidence declared alongside, which the kernel resolves after relations. The spec's doc says so; the first draft of the round-trip test assumed otherwise and the kernel's own validation corrected it.
- The kernel requires a non-structural relation to carry `confidence` and a `why` — a claimed link without a stated reason is exactly what a memory must not hold. A contract test proves the refusal.
