## Author's change description

## What changed

This PR packages three related changesets that were already split into separate commits:

- harden the evaluation path by removing insecure TLS bypass usage, aligning benchmark model IDs, and patching `async-nats` through a vendored override so the workspace no longer resolves the vulnerable `rustls-webpki 0.102.8` path
- reduce complexity in benchmark reporting and diagnostic helpers by extracting repeated logic and simplifying noisy conditionals
- add optional NATS and Valkey metric exporters in the Helm chart and wire the OTel collector to scrape them when enabled

## Why it changed

There were two concrete problems in the current branch state:

- the evaluation harness still allowed disabled certificate validation and the lockfile still resolved the vulnerable `rustls-webpki 0.102.8` path through `async-nats`
- the chart exposed no built-in metrics path for NATS or Valkey, which limited self-contained observability

The reporting refactors are included because they are low-risk cleanups on the same benchmark/evaluation surface and had already been validated locally.

## Impact

- evaluation runs now require valid TLS certificates instead of silently accepting invalid ones
- benchmark smoke configuration is smaller and documented explicitly
- the chart can expose NATS and Valkey metrics through exporters and the OTel collector can scrape them into the existing metrics pipeline
- operations docs now reflect the current deployment boundary, especially the current Neo4j limitation in the self-contained mTLS profile
