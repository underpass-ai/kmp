## Author's change description

## What changed

This branch closes the contract-validation phase for PIR integration work.

It adds:
- a new in-cluster kernel contract runner for sync gRPC and async NATS+gRPC validation
- blind graph extraction, structural evaluation, and blind context-consumption smokes
- evidence documents for the blind structural and blind context-consumption slices
- an updated PIR integration plan showing slices 1-5 complete and slice 6 as the next phase
- OTEL cleanup for the bundled collector path, including stable service naming and explicit trace-export disablement when traces are not configured

## Why it changed

The goal is to stop hand-waving about the PIR↔kernel boundary and replace it with reproducible evidence.

After this branch, the contract has been validated on the path that matters:
- model extraction
- semantic reranking
- kernel publish
- kernel rehydration
- downstream model answer from `rendered_content`

## User and developer impact

- cluster validation is now reproducible through the kernel contract runner
- blind fixtures reduce prompt leakage compared with the earlier strong fixtures
- documentation now reflects actual progress rather than the earlier planned-only state
- the next phase can focus on the first real PIR adapter instead of more contract scaffolding

## Root cause / rationale

Before this work, we had good partial proofs but they were split across local tests, ad-hoc jobs, and strong fixtures. That made it too easy to overstate what had actually been proven.

This branch consolidates the runner, weakens the extraction fixture, records the evidence, and updates the plan to match reality.
