## Author's change description

Closes milestone **E1** of the [KMP Embedded Edition Roadmap](https://github.com/underpass-ai/rehydration-kernel/blob/23bce7ee77c9e57aef7ad9b0694e0959e7fabd83/docs/product/kmp-embedded-edition-roadmap.md) — the keystone that turns the embedded edition into an adapter project instead of a rewrite risk.

## What's here

**`rehydration-conformance`** — 16 scenarios expressed ONLY in domain ports + application services (no gRPC, no MCP, no adapter types): write→read coherence, ensure/upsert + placeholder semantics, depth-bounded directed traversal, context paths, incoming/outgoing relationships, about index (plain + by-dimension), detail last-write-wins, projection-event dedup by `event_id`, replay convergence, ingest read-after-write, dry-run, idempotency conflicts, known-at-time temporal moves (goto/near/rewind/forward), relation proof via inspect, and trace paths.

**Two arms, same suite:**
| Arm | Backend | Where it runs | Result |
| --- | --- | --- | --- |
| (a) | `InMemoryKernelStore` (new in testkit) | workspace `test` job | 16/16 in ~1.7s |
| (b) | Neo4j + Valkey containers (all five Valkey stores incl. `ValkeyContextEventStore`) | new `integration-conformance` job | 16/16 in ~17s |

**`InMemoryKernelStore`** replaces nothing — the fixture-style stores stay for existing tests — but is the first in-memory implementation with real write→read coherence: `apply_mutations` writes what every read port reads, BFS mirrors the Neo4j Cypher semantics (directed outgoing, depth-bounded, placeholder `MERGE ON CREATE` behavior, empty-neighborhood relation quirk), details mirror Valkey last-write-wins. It is the reference implementation the E2 redb adapters will be built against.

## Also
