## Author's change description

## What

The recall side of the consumer contract grows what its last deep-importing consumer needs:

- **`MemoryRecallView.revision` + `.content_hash`** — the snapshot's identity. Two recalls answering with the same pair saw one memory state; a consumer combining a wake and an ask checks this instead of hoping. Deliberately distinct from `rendered.content_hash`, which covers the rendered text — a contract that reused one for the other would let a consumer verify the wrong thing (a contract test asserts they differ).
- **`RenderedMemoryView.quality: MemoryQualityView`** — the kernel's own account of the trade its rendering made: raw equivalent tokens, compression ratio, causal density, noise ratio, detail coverage. Ratios are `f64`, so the views holding them move from `Eq` to `PartialEq` — the honest derive.

## Why now

The embedding product's precedent search adapter and bundle mapper still deep-import `GetContextResult` / `RehydrationBundle` for exactly two reasons: the `same_snapshot()` coherence check (bundle metadata) and `kmp.quality.*` telemetry (bundle quality metrics). With these two views published, that migration closes the recall side of ADR-0023's boundary.
