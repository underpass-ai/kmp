## Author's change description

Second piece of milestone **E3**: local, persistent, bounded quality telemetry for the embedded edition — per [ADR-014](https://github.com/underpass-ai/rehydration-kernel/blob/94f192dbaef8a2b385398fffe33e31e532230cbb/docs/adr/ADR-014-embedded-quality-telemetry.md).

```
QualityMetricsObserver (ADR-007 port)
        │ try_send (bounded, fail-open)
BufferedQualityMetricsObserver ──► EmbeddedTelemetryGuard worker ──► telemetry/quality.redb
                                                                          │
                                                              RedbQualityTelemetryReader
```

- **Separate file** from `kernel.redb`: telemetry has its own retention and relaxed durability (no fsync per batch — losing the tail on crash is fine, losing memory is not)
- **Fail-open by contract**: `observe()` never blocks or fails the kernel; overflow drops and counts
- **Runtime-neutral worker** (plain OS thread, named, explicit shutdown) — works from any host
- Embedded MCP backend journals `kernel_wake`/`kernel_ask`/`kernel_trace` quality (compression ratio, causal density, noise, detail coverage); e2e test polls the journal
- Windowed read surface: `query_since`/`query_between`/`latest`/`count` — CLI query subcommand is the planned next step (deliberately NOT an MCP tool: one-protocol rule)
- Docs: ADR-014 + `docs/integrations/choreographer-kmp.md` (integration guide for the incident-resolution agent, with open questions inline)
