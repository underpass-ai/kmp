## Author's change description

Core of milestone **E3** of the [KMP Embedded Edition Roadmap](https://github.com/underpass-ai/rehydration-kernel/blob/58a635799282ff6decf55be88a82602fb93f30b8/docs/product/kmp-embedded-edition-roadmap.md): `REHYDRATION_MCP_BACKEND=embedded` runs the full kernel inside the MCP stdio binary — no Neo4j, no Valkey, no NATS, no gRPC endpoint.

## Design: identical JSON by construction

Instead of duplicating the tool JSON shaping (drift risk between editions), the embedded backend **reuses the exact live-mode path** minus the network:

```
tool args ──(existing builders)──> proto request ──(rehydration-proto-mapping)──> application query
                                                                                        │ in-process
tool JSON <──(existing kmp.rs)──── proto response <──(rehydration-proto-mapping)── application result
```

- **`rehydration-proto-mapping`** (new): the proto↔application mapping extracted verbatim from `transport-grpc` (which now re-exports it) — one shared mapping for every consumer of the v1beta1 contract
- **`rehydration-embedded`** (new): composition root — application services over `EmbeddedKernelStore` with synchronous projection; ADR-012 data-dir resolution (`REHYDRATION_MCP_DATA_DIR` > project `.kernel/` self-gitignoring > XDG) with the winning rule logged; ADR-011 single-writer fail-fast
- **`rehydration-mcp`**: `EmbeddedKernelMcpBackend` + env arm; e2e test proves ingest → wake → **new session on the same data dir recovers the memory** (the fresh-machine criterion in miniature)

## Measured

13.0MB stripped release binary carrying both `live` and `embedded` backends — above ADR-013's single-digit target, recorded honestly; the feature split remains the lever if it matters.
