## Author's change description

## What changed

This slice groups three related changes needed before the next PIR integration step:

- add a writable `/tmp` volume to the kernel deployment and the Helm e2e test pod while keeping `readOnlyRootFilesystem=true`
- simplify the large live vLLM soak to a single `primary -> semantic reranker -> roundtrip` path
- add PIR-oriented live smoke coverage and documentation for the next real integration step

## Why

We are still in the contract-validation phase for `PIR -> kernel`.
This PR strengthens that phase in three ways:

- the Helm change removes the scratch-space issue seen in restricted pods/jobs
- the soak change removes the old repair-judge variant from the long test and aligns it with the reranker-backed path we actually want to validate
- the new PIR smoke and planning docs make the next slice explicit: stable-identity waves, kernel rehydration, and LLM consumption of `rendered.content`

## User and developer impact

- the kernel chart is safer to operate with read-only rootfs because `/tmp` is now explicitly writable
- the long live soak is simpler and closer to the intended runtime shape
- the repo now documents and partially implements the live PIR incremental consumption path, including reranker use before publish

## Root cause

The repo already had the contract reference for PIR, but not a single place that turned it into an execution plan for the real integration. We also still had a long soak shape carrying the older repair-judge branching, and we had observed scratch-space problems in read-only pods without an explicit `/tmp` mount.
