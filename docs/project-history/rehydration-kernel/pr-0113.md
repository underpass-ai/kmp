## Author's change description

## Summary

Companion docs PR to the operator-trainer change
(underpass-kmp-operator-trainer#53). A 2026-05-29 forensic audit found the v7/v8
operator SFT path shipped **un-anonymized domain refs**, contradicting this repo's
own model plan (`kernel-tool-operator-model-plan.md`: opaque-ref requirement,
*"the operator only learns to use KMP"*). These are doc-only banners that bring the
operator product docs in line with the corrected design.

## Changes
- `operator-training-experiment-process.md`, `operator-training-run-template.md`:
  reference anonymization is now a mandatory, recorded gate; no model is publishable
  with anonymization OFF.
- `huggingface/*-card-template.md`: publication gate requires anonymized refs; v8.x
  models are not publishable until re-anonymized + retrained.
- `kernel-tool-operator-model-plan.md`: marked the pre-v8-divergence design baseline
  with a pointer to the corrective record.
- `kernel-tool-operator-publication-plan.md`: addendum — un-anonymized models fail
  the gate. `operator-training-runs/README.md`: dated divergence timeline.

## Note
The read-nav "cliff" was ultimately diagnosed as a **missing-schema eval-prompt bug**,
not anonymization (the model is strong once served the MCP/API schema). Anonymization
remains a real, separate design requirement. Full analysis is in the operator repo PR.
