## Author's change description

## Summary
- wire the OTLP trace and metric exporters to actually honor `OTEL_EXPORTER_OTLP_ENDPOINT`
- switch the in-chart collector auto-wiring to `https://...:4317` when `otelCollector.tls.enabled=true`
- mount the OTel TLS secret into the kernel pod and validate that TLS config is complete in Helm
- update docs and Helm lint coverage for the mTLS collector path

## Root cause
The observability crate read `OTEL_EXPORTER_OTLP_ENDPOINT` but never applied it to the OTLP exporter builder. On the chart side, the kernel deployment still hardcoded `http://...:4317` for the collector and did not mount the collector TLS material into the kernel pod.

## Impact
Kernel pods in mTLS deployments now point to the collector with the correct scheme and have access to the OTLP client certificate material. This removes a silent miswiring in the kernel-to-collector path.
