## Author's change description

## What

- Adds **`docs/operator.md`**: a canonical, agent-readable explainer for what *Operator* is — and is not.
- Adds a visible **note in the README** (right after "What the kernel is NOT") pointing to it, and reframes the operator references so the architecture diagram shows KMP operated **directly** by any capable model (no operator on the path).

## Why

Operator is easy to misread (treated as a production layer, or as competing with frontier models). This documents the calibrated truth so any contributor — human or agent — reasons about it correctly:

- **Operator is not KMP, and KMP is not built for Operator.** KMP is designed to be easy to use by **people and agents** — hence its MCP/typed-API duality — and would exist unchanged with no operator at all.
- **Operator is a separate, external, benchmark-only project.** The kernel does not depend on it. Any capable frontier model operates KMP directly via MCP and would never route through it.
- **gpt-4o is used only because LongMemEval's official judge requires it** (`evaluate_qa.py gpt-4o`, repo `xiaowu0162/LongMemEval`, arXiv 2410.10813) — not by choice; the operator covers gpt-4o's KMP-write weakness in that mandated setting.
- **Bounded claim:** a small model trained specifically to use an API can match a 4o / 4o-mini-class model at using it — never positioned above a frontier model.
