## Author's change description

## Summary

Fixes the last P0 from the external architecture review.

`UpdateContext` was fabricating `snapshot_id` and returning `snapshot_persisted: true` without persisting any real snapshot. This was misleading command-surface semantics.

### Fix
- Remove `persist_snapshot` and `snapshot_persisted`/`snapshot_id` from the application command and outcome structs
- Transport accepts `persist_snapshot` from proto (wire compat) but ignores it, always returning `false`/empty
- Document in beta-status.md that snapshot persistence is the query path's responsibility
- Soften README from "functionally complete" to "usable beta"

### Why not implement real snapshots in the command?
Snapshot construction requires reading the graph state — that's a query, not a command. Mixing both in `UpdateContext` violates CQRS. If a caller wants a snapshot after an update, they call `RehydrateSession` with `persist_snapshot: true`.
