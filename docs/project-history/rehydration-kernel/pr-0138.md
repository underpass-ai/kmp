## Author's change description

## What changed

- Gate OpenTelemetry/OTLP dependencies behind the `otel` feature of `rehydration-observability`.
- Keep deployed consumers explicitly opted into OTEL while the in-process embedded kernel uses only the buffered local observer and Redb journal.
- Add a dependency-graph gate that rejects OpenTelemetry, HTTP, protobuf and gRPC clients from `rehydration-embedded`.
- Record the binary boundary in ADR-014 and update the E3 roadmap status.

## Why

The local quality journal is zero-infrastructure at runtime, but its crate still linked the remote OTLP stack transitively into every embedded consumer. That made the distribution heavier and broke the intended small-surface contract even when no collector was configured.

## Impact

Embedded consumers retain `telemetry/quality.redb`, fail-open buffering and the existing domain port without linking remote observability clients. Server and gRPC deployments keep their current OTEL behavior through explicit feature activation.
